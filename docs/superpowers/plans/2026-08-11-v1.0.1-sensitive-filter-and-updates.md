# 粘易 V1.0.1 Sensitive Filter and Updates Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver 粘易 `1.0.1 (2)` with an opt-out sensitive-content filter, runtime version information, and secure Sparkle updates distributed through GitHub Releases.

**Architecture:** Keep sensitive filtering in the existing `PrivacyService`, but drive it from persisted settings read on every capture. Add isolated version and update-service abstractions for the Settings UI, with Sparkle 2.9.2 providing scheduling, verification, installation, and restart. Host signed ZIP assets in GitHub Releases and the generated appcast in `docs/appcast.xml` through GitHub Pages.

**Tech Stack:** Swift 6, SwiftUI, AppKit, Combine, XCTest, XcodeGen, Sparkle 2.9.2, App Sandbox XPC services, Bash release verification, OpenSpec, GitHub Releases, GitHub Pages.

## Global Constraints

- Read and follow `AI_CODING_RULES.md` before every implementation session.
- Keep the deployment target at macOS `14.0` and preserve bundle identifier `com.peibin.MacPasteHistory`.
- Use version `1.0.1` and monotonically increasing build number `2`.
- Sensitive-content filtering defaults to enabled for new and upgraded installations.
- Never log clipboard payloads, signing keys, tokens, passwords, or appcast private-key material.
- The local SQLite database remains unencrypted; the disable-filter confirmation must state that risk.
- Keep `com.apple.security.network.client` disabled on the main app; use Sparkle Downloader XPC for update networking.
- Use HTTPS, Sparkle EdDSA signatures, Developer ID signing, and Apple notarization for formal update artifacts.
- Store Sparkle's private EdDSA key only in the publisher's Keychain or protected release environment; commit only the public key.
- Do not publish a GitHub Release, enable GitHub Pages, push, or modify remote resources without explicit user approval at execution time.
- Use synthetic test tokens only; do not copy the user-provided credential into source, tests, logs, fixtures, or documentation.

- [ ] **Step 4: Implement `UpdateService`**

```swift
import Combine

@MainActor
protocol UpdateDriving: AnyObject {
    var canCheckForUpdatesPublisher: AnyPublisher<Bool, Never> { get }
    var automaticallyChecksForUpdates: Bool { get set }
    func checkForUpdates()
}

@MainActor
final class UpdateService: ObservableObject {
    @Published private(set) var canCheckForUpdates = false
    @Published private(set) var automaticallyChecksForUpdates: Bool
    private let driver: UpdateDriving

    init(driver: UpdateDriving) {
        self.driver = driver
        automaticallyChecksForUpdates = driver.automaticallyChecksForUpdates
        driver.canCheckForUpdatesPublisher
            .removeDuplicates()
            .receive(on: RunLoop.main)
            .assign(to: &$canCheckForUpdates)
    }

    func checkForUpdates() {
        guard canCheckForUpdates else { return }
        driver.checkForUpdates()
    }

    func setAutomaticallyChecksForUpdates(_ enabled: Bool) {
        driver.automaticallyChecksForUpdates = enabled
        automaticallyChecksForUpdates = driver.automaticallyChecksForUpdates
    }
}
```

@MainActor
final class SparkleUpdateDriver: UpdateDriving {

            startingUpdater: startingUpdater,

    var canCheckForUpdatesPublisher: AnyPublisher<Bool, Never> {
        controller.updater.publisher(for: \.canCheckForUpdates).eraseToAnyPublisher()
    }

    var automaticallyChecksForUpdates: Bool {
        get { controller.updater.automaticallyChecksForUpdates }
        set { controller.updater.automaticallyChecksForUpdates = newValue }
    }

    func checkForUpdates() {

    }
}
