## 4. V1.0.3 升级假设

1. V1.0.3 必须直接打开有效的 V1.0.2 build 4 数据库，不允许通过删除或重建 `clipboard.db` 完成升级。
2. 已发布的 V1–V4 migration 不得修改；如确需 schema 变化，只能追加下一个递增 migration。
3. 捕获来源一致性、Sensitive Detector V2、搜索取消、PasteCoordinator 和 ViewModel 拆分默认不需要 schema 变化。
4. Storage Reconciliation 首先以 inventory/plan 模式建立证据；只有可证明属于应用管理目录且修复动作幂等时才允许变更文件。
5. SQLite WAL 不是既定交付，必须与当前 journal mode 使用同一套并发、重开、回滚和旧库升级测试比较后决定。

## 5. 回滚边界

- 每个 TDD Task 使用独立、可审查 commit，RED 与 GREEN checkpoint 均必须位于 `release/v1.0.3` 当前历史。
- 无 schema 变化的任务可以按 commit 回滚，不得删除用户数据库或图片。
- 如果追加 migration，回滚旧应用时必须仍能读取既有核心表；不得以降级脚本删除用户字段或数据。
- Tag、签名、公证、Sparkle 包、GitHub Release 和 appcast 不属于本开发任务；在这些外部动作发生前，版本回滚只涉及本地 Git 分支。
