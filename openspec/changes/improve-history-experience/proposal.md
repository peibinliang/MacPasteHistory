## Why

Once text history exists, the app needs a more usable browsing experience so long content, favorites, filters, and larger datasets do not make the panel hard to use. This phase improves history interaction without changing the core capture model.

## What Changes

- Improve history list styling and row readability.
- Add multi-line text previews that do not break layout.
- Add a history detail view for full content.
- Add favorite and unfavorite behavior.
- Add a dedicated favorites list.
- Add basic content type filtering.
- Display user-friendly relative or absolute copy times.
- Add lazy loading to keep large lists responsive.

## Capabilities

### New Capabilities
- `improve-history-experience`: History list presentation, detail viewing, favorites, basic filters, relative time display, and lazy loading.

### Modified Capabilities

## Impact

- Affects history list views, row components, detail presentation, repository queries, favorite state, filtering state, and list loading strategy.
